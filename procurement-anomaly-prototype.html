Federal Procurement Anomaly Prototype

Demonstration only. This is a synthetic-data work sample, not a client engagement, fraud finding, contract win, or claim of prior project experience. Production work would use official USAspending.gov data and preserve source identifiers.

Purpose

Show a compact, explainable workflow for flagging federal procurement transactions for human review without asserting wrongdoing.

Example output

Award IDVendorAward AmountRisk ScoreFlaggedReasons
SYN-001Vendor A$2,450,00086YAmount far above peer median; single-source indicator
SYN-002Vendor B$118,00022NNo material rule-based indicators
SYN-003Vendor C$640,00071YHigh vendor award frequency; elevated anomaly score

Method

Prepare transaction-level fields such as award ID, recipient, amount, action date, product/service category, number of offers and competition status. Standardize numeric features, run an unsupervised outlier model such as Isolation Forest, and combine its anomaly signal with transparent rule indicators.

Illustrative scoring: 0–40 model anomaly component + 0–25 unusual-amount component + 0–20 vendor-frequency component + 0–15 limited-competition component. Scores rank records for review; they do not determine fraud.

Human-readable explanations

Every flagged row should carry deterministic reasons, e.g. award amount is 7.8× category median, vendor frequency is in top 1%, or competition field indicates one offer. This makes the output auditable and useful to an investigator.

Deliverables

CSV/JSON results, reproducible Python pipeline, field dictionary, scoring notes, source/query record, and a short limitations memo. Production implementation would validate official-source fields and avoid unsupported allegations.
